# rn-fabricator v1.0.0-beta.1

Release date: 2026-06-26

## Summary

This beta release promotes local template lifecycle management to a first-class rn-fabricator workflow. Fabricator-created projects now keep user-facing template state in root `fabricator.json`, reusable templates can be added, updated, removed, validated, and applied from local catalogs, and dry-run support makes project and catalog changes reviewable before writes happen.

## Added

- Root `fabricator.json` state generation for projects created with the minimal starter.
- Template source resolution from:
  - explicit `--source`
  - `RN_FABRICATOR_TEMPLATE_SOURCE`
  - root `fabricator.json`
  - conventional `./templates/catalog.fabricator.json`
- `templates status --project <project>` for inspecting applied template history and catalog version status.
- `templates add <template> --category <folder-key> --from <project> --source <catalog>` for capturing and registering new local templates.
- `templates update <template> --from <project> --source <catalog>` for refreshing existing local templates from Fabricator project folders.
- `templates remove <template> --source <catalog>` for removing local catalog entries while keeping template folders by default.
- `--dry-run` support for apply, add, update, and remove template lifecycle commands.
- Focused beta readiness tests for create state generation, local source resolution, validation diagnostics, apply state tracking, duplicate apply behavior, lifecycle dry-runs, and missing or invalid `fabricator.json`.

## Changed

- Template command output now uses consistent `Summary:` and `Next:` lines.
- `templates apply` reports whether root `fabricator.json` state tracking was updated or skipped.
- Local template lifecycle documentation now covers repo-external playground testing, local catalog workspaces, dry-run-first workflows, and manual integration limits.

## Fixed

- `templates validate` accepts Fabricator project folder categories such as `screens`, `components`, `services`, and `utils` for templates captured with local lifecycle commands.

## Safety Boundaries

- Existing project files are skipped unless `--overwrite` is provided.
- Existing barrel exports are not duplicated.
- `templates add`, `templates update`, and `templates remove` require local filesystem catalogs for write operations.
- Remote GitHub raw catalogs are read-only sources for list, info, validate, copy, and apply.
- `templates remove` keeps template folders unless `--delete-files` is explicitly provided.
- Fabricator does not edit arbitrary imports, navigation registration, menu wiring, dependency installation, secrets, or environment configuration automatically.
