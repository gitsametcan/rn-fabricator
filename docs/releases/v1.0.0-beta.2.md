# rn-fabricator v1.0.0-beta.2

Release date: 2026-06-27

## Summary

This beta release improves the reusable template workflow by allowing developers to save and refresh individual files or small feature slices from Fabricator-compatible projects. A template no longer has to capture an entire project folder when the developer only wants one screen, component, service, utility, or a selected group of related files.

## Added

- Repeatable `--include <project-relative-path>` support for:
  - `templates capture`
  - `templates add`
  - `templates update`
- Selected-file capture for single screens, components, services, utilities, and small feature slices.
- Target folder mapping from the Fabricator project contract for selected files, so paths such as `src/screens/ProfileScreen.tsx`, `src/components/ProfileHeader.tsx`, and `src/services/profileApi.ts` apply back to their expected project folders.
- Tests covering selected-file capture, selected-file add, selected-file update, multi-folder file selection, invalid include paths, and apply compatibility.

## Changed

- Existing folder-level capture behavior remains the default when `--include` is omitted.
- Reusable template workflow documentation now explains when to use folder-level templates and when to use selected-file templates.
- Dogfooding documentation now includes examples for capturing, adding, and updating a single `FabricatorBeta.tsx` screen.

## Safety Boundaries

- Included paths must be project-relative files.
- Rooted paths, parent traversal, missing files, directories, and files outside known Fabricator project folders are rejected.
- Existing project files are still skipped during apply unless `--overwrite` is provided.
- Local catalog write operations still require filesystem catalog paths.
